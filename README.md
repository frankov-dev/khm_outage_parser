# Khmelnytskyi Outage JSON Parser

Автоматизований скрапер і парсер графіків погодинних відключень електроенергії (ГПВ) з офіційного сайту АТ «Хмельницькобленерго» ([hoe.com.ua](https://hoe.com.ua/page/pogodinni-vidkljuchennja)), який кожні **15 хвилин** оновлює та зберігає структуровані JSON-файли в папці `docs/` через **GitHub Actions**.

---

## 📁 Структура проєкту та згенерованих файлів

```text
khm_outage_parser/
├── .github/workflows/
│   └── update_and_deploy.yml   # Автоматичний запуск кожні 15 хв + коміт JSON у репо
├── src/
│   ├── scraper.py              # Скрапер hoe.com.ua (основна сторінка + розділ новин)
│   ├── parser.py               # Парсер розкладу, інтервалів та оперативних змін
│   └── exporter.py             # Експортер JSON із підтримкою ревізій за день та хешування
├── docs/
│   ├── status.json             # Легковаговий (~250B) файл метаданих і хешу для швидкого пулінгу
│   ├── today.json              # Графік конкретно на сьогоднішню добу (за київським часом)
│   ├── tomorrow.json           # Графік на завтра (з прапорцем available: true/false)
│   ├── latest.json             # Найновіший опублікований графік (сумісний зі старим API)
│   ├── outages.json            # Повна база за останні 14 днів (сумісний зі старим API)
│   └── schedules/
│       └── YYYY-MM-DD.json     # Окремий файл графіка для кожної дати
├── tests/                      # Юніт-тести (50+ тестів)
├── run.py                      # Точка входу (CLI)
└── requirements.txt
```

## ⚙️ Принцип роботи парсера (End-to-End Pipeline)

### 1. Збір даних (`src/scraper.py`)
1. **Основна сторінка (`/page/pogodinni-vidkljuchennja`):**
   * Скрапер завантажує HTML сторінки ГПВ (із механізмом ретраїв та експоненційною затримкою).
   * Розділяє контент на окремі блоки графіків за тегами `<hr>` або за новими заголовками-оголошеннями (`«За розпорядженням НЕК "Укренерго"...»`), якщо редактор сайту забув поставити `<hr>`.
   * Автоматично відкидає довідкові таблиці РЕМів, посилання на PDF/XLSX та стандартні шаблонні дисклеймери внизу сторінки.
2. **Проактивна перевірка розділу Новин (`/post/novini-kompaniji`):**
   * Якщо на головній сторінці ще немає графіка на **завтра** (або якщо головна сторінка порожня), скрапер перевіряє розділ новин компанії.
   * **Трирівневий фільтр новин:**
     1. *Фільтр URL та заголовків:* відкидає статті-роз'яснення (`chomu-...`, `pitannjavidpovid...`, новини зі знаком `?`) і шукає лише URL цільових графіків (`prognoz-gpv-na-...`, `pogodinni-vidkljuchennja-na-...`, `grafik-vidkljuchen-na-...` тощо).
     2. *Фільтр вмісту:* ігнорує будь-яку сторінку, де немає ключових слів підчерг (`підчерга 1.1`..`6.2`).
     3. *Фільтр інтервалів:* якщо в тексті немає валідних часових інтервалів або явної вказівки про відсутність відключень, блок відкидається.
3. **Визначення дати:**
   * Підтримує текстові дати (`23 листопада`, `15 січня 2026`), числовий формат (`23.11.2026`, `08.04.26`) та legacy `alt` у картинок (`ГПВ-15.01.26`).
   * Ігнорує технічні таймстемпи в дужках на кшталт `(оновлено о 23:00, 15.11.2026)` при визначенні цільової дати графіка.
   * Автоматично виправляє очевидні одруківки року від редакторів сайту (наприклад, `2027` замість `2026`) та коректно обробляє перехід року (31 грудня -> 1 січня).

### 2. Парсинг розкладу та оперативних змін (`src/parser.py`)
* Розпізнає сучасний формат (`Підчерга 1.1 – 10:00-15:00; 18:00-22:00.`), класичний формат (`з 10:00 до 15:00`) та групові рядки (`Підчерги 3.1, 3.2 – ...`).
* **Гарантія всіх 12 підчерг:** у кожному валідному графіку **завжди присутні всі 12 ключів** (`"1.1"`, `"1.2"`, ..., `"6.2"`). Якщо для черги написано `«вимкнень немає»` / `«без відключень»` або вона не згадана в переліку, для неї повертається `{"intervals": [], "total_hours_off": 0.0}`.
* Застосовує оперативні зміни (*«розпочнеться раніше о HH:MM»*, *«триватиме довше до HH:MM»*, *«додатково з HH:MM до HH:MM»*) із захистом від утворення невалідних інтервалів (`start < end`) та автоматичним злиттям перетинів.

### 3. Збереження історії змін за день та експорт (`src/exporter.py`)
* **Історія ревізій за день (`previous_schedules`):**
  * Коли обленерго публікує оновлений графік на сьогодні (наприклад, *«оновлено з 11:00»*), найновіший графік записується в основні поля `queues` та `operational_message`.
  * Попередній графік за цей самий день (як зі сторінки під лінією `<hr>`, так і з попереднього стану `outages.json`) **не втрачається**, а автоматично переноситься в масив `previous_schedules`.
* **Захист від зайвих комітів і перехід доби (Midnight Rollover):**
  * Якщо графіки не змінилися, файли не перезаписуються.
  * Опівночі за київським часом (`00:00 Europe/Kyiv`) автоматично оновлюються `today.json`, `tomorrow.json` та `status.json`, щоб `today.json` переключився на нову добу.

## 📱 Гайд для розробників Android-застосунку (Що змінилося та як оновити клієнт)

> **Зворотна сумісність:** Формат існуючих файлів `latest.json` та `outages.json` **100% зворотно сумісний**. Старі версії Android-застосунку продовжать працювати без жодних правок (додалися лише нові поля `schedule_hash` та `previous_schedules`).

### Що було проблемою раніше і як це вирішено зараз:
1. **Проблема вечірнього графіка на завтра:** раніше, коли о 20:00 виходив графік на завтра, `latest.json` одразу перезаписувався завтрашньою датою, і користувач о 20:30 більше не бачив у `latest.json` розклад на залишок сьогоднішнього вечора.
   * **Рішення:** додано окремі файли **`today.json`** (завжди сьогоднішній день) та **`tomorrow.json`** (завтрашній день із прапорцем `"available": true | false`).
2. **Зникнення підчерг без відключень:** раніше, якщо у підчерги не було вимкнень, ключ (наприклад, `"2.1"`) був відсутній у `queues`.
   * **Рішення:** тепер в об'єкті `queues` активного дня **завжди є всі 12 підчерг (`1.1`..`6.2`)**. Якщо відключень немає — `"intervals": []`, `"total_hours_off": 0.0`.
3. **Втрата попереднього графіка після оновлення:** раніше ранковий графік перезаписувався денним оновленням безслідно.
   * **Рішення:** додано масив **`previous_schedules`**, де лежать попередні версії графіка за цей день (можна показувати в UI блок *«Попередня версія графіка»* або порівнювати зміни, щоб підсвітити користувачу `+2 год` / `-1 год`).
4. **Зайвий трафік при фонових перевірках (WorkManager):**
   * **Рішення:** додано крихітний файл **`status.json`** (~250 байтів) із полем `schedule_hash`.

### 🔗 Рекомендований флоу запитів для Android-клієнта

Базовий URL:
```text
https://raw.githubusercontent.com/frankov-dev/khm_outage_parser/master/docs/
```

> **Порада щодо частоти оновлень у GitHub Actions:** GitHub може затримувати вбудовані `schedule` cron-запуски на публічних репозиторіях у години пікового навантаження. Для гарантованого 15-хвилинного інтервалу можна безкоштовно викликати `workflow_dispatch` через зовнішній планувальник (наприклад, Cloudflare Workers Cron або cron-job.org).

#### Крок 1. Фонова перевірка оновлень (`GET /docs/status.json`)
Раз на 15 хвилин у фоновому `WorkManager` або при старті додатка стягуйте `status.json`:
```json
{
  "source": "https://hoe.com.ua/page/pogodinni-vidkljuchennja",
  "last_updated": "2026-11-23T18:03:41.470735+02:00",
  "schedule_hash": "d7e04ca75c99606d",
  "latest_date": "2026-11-23",
  "today_date": "2026-11-23",
  "tomorrow_date": null,
  "has_tomorrow": false,
  "available_dates": [
    "2026-11-23",
    "2026-11-22",
    "2026-11-21",
    "2026-11-20"
  ]
}
```
* Порівняйте `schedule_hash` зі збереженим у `SharedPreferences` / `DataStore`.
* Якщо `schedule_hash` **не змінився** — мережеві запити завершено, читаємо дані з локального кешу!
* Якщо `schedule_hash` **змінився** — завантажуємо `today.json` (і `tomorrow.json`, якщо `has_tomorrow == true`) та надсилаємо користувачу Push-сповіщення, якщо інтервали його черги змінилися.

#### Крок 2. Вкладка «Сьогодні» (`GET /docs/today.json`)
Завжди повертає розклад на поточну добу за Києвом:
```json
{
  "source": "https://hoe.com.ua/page/pogodinni-vidkljuchennja",
  "last_updated": "2026-11-23T18:03:41.470735+02:00",
  "schedule_hash": "d7e04ca75c99606d",
  "date": "2026-11-23",
  "is_today": true,
  "operational_message": "За розпорядженням НЕК «Укренерго» оновлено графік погодинних відключень (ГПВ) на 23 листопада (оновлено з 11:00).",
  "queues": {
    "1.1": {
      "intervals": [
        { "start": "10:00", "end": "15:00", "type": "base" },
        { "start": "18:00", "end": "22:00", "type": "base" }
      ],
      "total_hours_off": 9.0
    },
    "3.1": {
      "intervals": [
        { "start": "11:00", "end": "13:00", "type": "base" },
        { "start": "15:00", "end": "20:00", "type": "base" }
      ],
      "total_hours_off": 7.0
    }
  },
  "previous_schedules": [
    {
      "operational_message": "За розпорядженням НЕК «Укренерго» 23.11.2026 р. на Хмельниччині будуть застосовані графіки погодинних відключень (ГПВ).",
      "queues": {
        "3.1": {
          "intervals": [
            { "start": "15:00", "end": "20:00", "type": "base" }
          ],
          "total_hours_off": 5.0
        }
      }
    }
  ]
}
```

#### Крок 3. Вкладка «Завтра» (`GET /docs/tomorrow.json`)
Коли графіка на завтра ще немає (`"available": false`):
```json
{
  "source": "https://hoe.com.ua/page/pogodinni-vidkljuchennja",
  "last_updated": "2026-11-23T18:03:41.470735+02:00",
  "schedule_hash": "d7e04ca75c99606d",
  "date": "2026-11-24",
  "available": false,
  "operational_message": null,
  "queues": {},
  "previous_schedules": []
}
```
Як тільки графік на завтра з'являється на сайті або в новинах, `"available"` стає `true`, а `"queues"` заповнюється всіма 12 підчергами.

#### Крок 4. Історія за конкретний день або за всі дні
* **Окрема дата:** `GET /docs/schedules/2026-11-23.json`
* **Усі дати за останні 14 днів одним файлом:** `GET /docs/outages.json`
